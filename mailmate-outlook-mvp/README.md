# Mailmate 邮件助手

Mailmate 是适用于 Chrome 和 Microsoft Edge 的 Outlook 网页扩展。用户在正常登录的 Outlook 邮件文件夹中点击一次“开始分析”，扩展会自动检查当前文件夹近两周的邮件项，并在结束后用右下角的列表卡片展示重要事项。

## 下载扩展

点击 [下载 Chrome / Edge 扩展安装包](https://github.com/Shengheshan/Mailmate/raw/refs/heads/mailmate-outlook-mvp/mailmate-outlook-mvp/Mailmate-Outlook-Extension.zip)。压缩包只包含扩展文件。解压后，选择直接包含 `manifest.json` 的文件夹加载。

## 获取 Groq API Key

插件使用你自己的 Groq API Key 调用模型，不需要把密钥发给 Mailmate 项目维护者：

1. 打开 [Groq Console](https://console.groq.com/) 并登录或注册账号。
2. 进入 [API Keys 页面](https://console.groq.com/keys)，创建一个专用于 Mailmate 的密钥。若页面要求选择 Project，请先选中要使用的项目。
3. 创建后立即复制密钥，并妥善保管。密钥相当于密码；不要截图公开、发到群聊，也不要写入代码或提交到 GitHub。若怀疑泄露，请在 Console 删除并重新创建。
4. 按下文安装扩展并打开 Outlook，在右下角 Mailmate 面板里粘贴密钥，再开始分析。

Groq 的模型访问权限、免费额度和速率限制按账户及模型而异，可能调整；使用前请查看 [账户限额](https://console.groq.com/docs/rate-limits) 和 [Groq API Quickstart](https://console.groq.com/docs/quickstart)。API Key 会自动保存在当前浏览器的插件本地存储中，刷新后仍可使用；清空输入框即可删除。该存储不是密码保险箱，请像密码一样妥善保管。

## 展示与交互

- 开始后先快速滚动邮件列表，统计日期可识别的近两周邮件数量；这一阶段不打开邮件，也不调用 AI。
- 统计完成后逐封分析邮件，显示当前处理序号、已完成数量 / 总数、精确百分比，以及根据本次 AI 请求平均耗时计算的剩余时间估算；随时可停止。
- 全部处理完成或用户主动停止后，结果集中显示在同一张列表卡片中；读取或模型请求连续失败时会先自动重试，重试耗尽后显示中断说明，不会提前进入汇总页。
- 列表列出重要性、分类、邮件摘要、标准化截止日期、截止日期原文、行动内容和完成勾选框。
- 默认按重要性排序，同级按截止日期升序排列；没有可识别截止日期的邮件排在后面。
- 可搜索摘要和行动，并按全部、未完成、已完成筛选。
- 列表右上角提供醒目的“返回继续分析”按钮；返回后点击“继续分析近两周邮件”，插件会复用已完成项目的缓存并处理尚未完成的邮件。
- 悬停摘要会先展示完整邮件摘要，再展示原文；点击摘要可查看完整正文。悬停截止日期原文可查看正文中的对应片段。
- 每封邮件同时生成中文和英文摘要及行动内容。完成后切换显示语言，列表会即时切换语言，不需要重复扫描。
- 本地缓存会保存结构化结果、邮件正文和行动完成状态。缓存命中时不会再次调用模型；如果发现旧缓存只有摘要、没有正文，会从当前已登录的 Outlook 页面补读正文并修复缓存，不会重新分析。
- 被跳过或失败的邮件会出现在“查看跳过 / 失败邮件”入口中，用户可按主题回到 Outlook 检查；连续重试后仍中断时，也可从说明页打开这份清单。

## 在 Chrome 或 Edge 中加载

1. 下载上方安装包并解压。也可以打开 [Mailmate 插件源文件目录](https://github.com/Shengheshan/Mailmate/tree/mailmate-outlook-mvp/mailmate-outlook-mvp)查看源文件。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，选择“加载已解压的扩展”。
4. 选择解压后的文件夹，确认其中可以直接看到 `manifest.json`、`content.js` 和 `background.js`。
5. 正常登录学校 Outlook，进入要分析的邮件文件夹并刷新页面。页面右下角会出现 Mailmate 按钮。

## 使用流程

1. 点击右下角的 Mailmate，选择显示语言并输入自己的 Groq API Key。
2. 勾选邮件分析授权，然后点击“开始分析近两周邮件”。每次开始前都会出现必做的未读保护指引：在 Outlook 设置中选择“邮件 → 邮件处理 → 标记为已读 → 不要自动标记为已读”，保存后返回 Mailmate 并勾选确认。插件无法直接读取学校 Outlook 的这项设置。
3. 邮件列表保持最新邮件优先。插件先快速扫描邮件列表，统计近两周邮件数量；这个阶段不会打开邮件或调用 AI。随后逐封读取并分析，界面会显示当前序号、完成数 / 总数、百分比和剩余时间估算。剩余时间按本次已完成的 AI 请求平均耗时计算，Groq 限流、网络变化或邮件读取速度可能使实际耗时不同。请保持此标签页打开，也可以随时点击“停止”。完成或停止后，列表卡片会展示已处理的结果。需要接着处理时，点击“返回继续分析”，再点“继续分析近两周邮件”。首次同步可能需要较长时间，耗时会随邮件数量增加。

## 数据与隐私

- 扩展仅在用户点击开始并确认授权后工作，范围限于当前 Outlook 文件夹中日期可识别的近两周邮件项。
- 用户通过学校提供的正常登录状态访问 Outlook。扩展不调用 Microsoft Graph，不读取密码、Cookie、访问令牌或 MFA 信息。
- 邮件正文会发送到 GroqCloud，在美国处理。邮件中的链接地址默认不发送；用户可自行选择是否附带。Groq 默认不保留推理请求的客户输入和输出，但系统可靠性或滥用监控所需的临时日志可能保留最长 30 天；可在 Groq Console 的 Data Controls 查看或启用 Zero Data Retention（ZDR）。请阅读 [Groq 数据说明](https://console.groq.com/docs/your-data)。
- Groq API Key 默认保存在当前浏览器的插件本地存储中，刷新页面后仍可使用；不会发送给 Mailmate 遥测或写入邮件分析缓存。该存储不是密码保险箱，请像密码一样保管；清空输入框即可删除。
- 不把共享 API Key 写进公开扩展包，因为下载者可以提取并使用密钥。若要免去用户输入，应由 Mailmate 后端保管密钥并转发请求。
- 本地缓存默认开启，保存邮件标识、双语结构化结果、邮件正文和完成状态；邮件正文保存在当前浏览器本地，供缓存命中时展示原文，不会发送到 Mailmate 遥测服务。关闭缓存或清除缓存后，后续运行会重新分析邮件。API Key 不写入本地缓存。
- 扩展不会主动设置已读状态，但扫描时会通过 Outlook 页面逐封打开邮件；必须关闭 Outlook 自动标记已读设置。若 Outlook 行为仍改变了邮件状态，请停止使用并检查邮件。

## 使用统计与错误诊断

插件面板中的使用统计开关默认开启，可随时取消勾选。每次打开 Mailmate 时，扩展会检查 Worker 和 D1 连通性并记录一次匿名打开事件；面板标题栏会显示连接状态，连接失败时会将事件暂存在本机重试。看板每 30 秒自动刷新。关闭遥测会清除待发送队列。部署步骤见仓库中的 [遥测后端部署说明](https://github.com/Shengheshan/Mailmate/blob/mailmate-outlook-mvp/mailmate-telemetry/README.md)。

AI 请求会按 Groq 速率限制排队。为减少等待，每封请求使用更短的双语输出提示词，省去不参与展示的邮件 ID、收件时间和默认关闭的链接标签，并根据实际 Token 用量与 Groq 响应中的实时 Token 限额校准排队；这也避免更高额度的账户被固定的免费额度拖慢。单次请求超过安全额度时，会保留邮件开头和结尾后压缩，并在结果中标明。请求节奏贴近当前账户限额并留有余量；账户限额仍可能导致自动重试。

启用后，Mailmate 会发送随机安装标识（可关联同一安装实例，但不包含真实姓名或邮箱）、日期、分析次数、缓存命中、扫描/跳过/失败计数、行动项总数与勾选完成数，以及 Groq 请求的状态码、错误码/类型、从邮件字段和正文片段中做过脱敏并截短的错误消息、请求 ID、模型、耗时、Token 用量和响应字符数。客户端错误仅发送阶段和类别，不发送堆栈。

不发送邮件正文、主题、发件人、邮件 ID、API Key 或成功生成的摘要/行动原文。诊断日志最多保留 30 天，随机标识的安装实例和最近行动计数最多保留 90 天。报表中的日活/周活/月活按安装实例估算，不等同于真实人数；任务“完成率”是用户在 Mailmate 中勾选的行动比例，不代表现实中的实际完成情况。

## 当前范围

- 仅扫描当前打开的 Outlook 文件夹，不会自动遍历其他文件夹或整个邮箱。若 Outlook 将多封邮件合并显示为会话，结果按列表中的会话项处理。
- 统计阶段只使用 Outlook 邮件列表上可识别的日期；无法识别列表日期的邮件会跳过，并列入待检查清单，提示统计范围可能不完整。分析阶段再逐封打开日期符合范围的邮件正文。
- 不读取附件。Outlook 网页结构变化可能影响邮件列表或正文识别。
- Groq 免费额度或速率限制可能暂停批量任务；扩展会自动重试。连续重试仍失败时显示中断原因和待检查邮件清单；开启本地缓存时，已完成结果会保留并可在之后继续分析时复用。
- 若 Groq 返回 413（请求体过大），扩展会逐步缩短发给模型的正文、保留开头和结尾后重试；仍失败时会停止本轮并列入待检查清单，不会把未完成的结果伪装成完整汇总。
- 旧版只含单一语言的缓存需要重新分析一次，以生成中英文版本。
- 当前版本由使用者提供自己的 Groq API Key，适合受控演示。面向更多用户提供服务前，应部署 Mailmate 后端管理模型凭据、请求、授权和数据保留。
